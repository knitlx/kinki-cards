# Дизайн: «Карточки для вечеринки»

Дата: 2026-10-11
Статус: утверждён

## Задача

Веб-приложение с общей колодой карточек для кинки-вечеринки. Участники
вступают в комнату, все видят одну и ту же активную карточку, синхронизация
мгновенная. Карточки не повторяются, пока колода уровня не закончится. Три
уровня: лёгкий (разгон), средний, хард. Ведущий выбирает уровень и управляет
колодой.

## Ключевые решения (утверждены)

- Хостинг: Next.js на Vercel (free).
- Realtime и хранение состояния: Supabase (free), Postgres + Realtime.
- Управление: только ведущий. Участники только смотрят.
- Уровни: три отдельные колоды с независимыми остатком и сбросом,
  переключение в любой момент.
- Карточки: пользователь предоставит текст; до этого — seed-заглушка.

## Архитектура

- Next.js (App Router) + TypeScript. Фронт и серверная логика (Route
  Handlers). Деплой на Vercel.
- Supabase:
  - Postgres — состояние комнат и колод.
  - Realtime (Broadcast + Presence) — рассылка событий и список онлайн.
- Вся игровая логика на сервере. Клиент только слушает канал и рисует.
  Это исключает рассинхрон и гонки.
- Без регистрации: вход по коду комнаты + имя. Ведущий получает host-токен.

## Модель данных (Supabase Postgres)

- `cards` — общая библиотека: `id, level(easy/medium/hard), body, body_en, sort`.
- `rooms` — `code(4-6 симв.), host_secret, current_level, active_card_id,
  status(lobby/playing/empty), updated_at`.
- `room_decks` — строка на (комната x уровень): `remaining_ids jsonb,
  used_ids jsonb`, снимок перемешанного порядка.

## Realtime

- Канал `room:<code>`.
- Presence — список онлайн-участников.
- Broadcast события: `card:drawn`, `level:changed`, `deck:reshuffled`,
  `deck:empty`.
- При входе/переподключении клиент делает snapshot-fetch текущего состояния,
  затем подписывается. Никто не теряет активную карточку.

## Логика хода (сервер, только с host-токеном)

- «Начать»: для каждого уровня берём id всех карточек уровня, перемешиваем
  (Fisher-Yates), пишем `remaining_ids`, `used_ids = []`.
- «Следующая»: атомарно берём `remaining_ids[0]` -> в `used_ids`, ставим
  `active_card_id`, broadcast всем.
- Смена уровня: меняет `current_level`; ведущий тянет карточку из нового
  уровня.
- Конец уровня: если `remaining_ids` пуст -> экран «Колода закончилась» +
  «Замешать сброс» (used -> remaining, перепутать) или переключить уровень.

## Экраны

1. Лендинг — создать комнату / войти по коду.
2. Лобби — код + ссылка/QR, список участников; у ведущего выбор уровня и
   «Начать».
3. Игра — крупная карточка (заголовок + текст + бейдж уровня), счётчики
   «осталось / сыграно», участники; у ведущего — «Следующая», переключение
   уровня, «Замешать сброс».
4. Пустая колода — два действия выше.

Всё mobile-first.

## Локализация

- Язык интерфейса: русский / английский. Переключение на лету, без перезагрузки.
- Переключатель RU/EN **всегда доступен и активен на всех экранах** (лендинг,
  лобби, игра, экран пустой колоды) — вынесен в постоянный шапку-бар.
- Выбор языка запоминается (localStorage) и восстанавливается при следующем входе.
- Переводятся и элементы интерфейса, и текст карточек. У карточки два текста:
  `body` (русский) и `body_en` (английский); показывается по выбранному языку.
- Реализация: лёгкий React-контекст со словарями ru/en (без маршрутной локализации).

## Права

Ведущий — всё. Участники — только смотрят. host-токен в localStorage, ведущий
остаётся ведущим после перезагрузки.

## Краевые случаи

- Авто-reconnect Realtime + snapshot.
- Атомарное взятие карточки (двойной клик не ломает).
- Неверный код комнаты.
- Пустая колода уровня.
- Перезагрузка участника -> видит текущую карточку.

## Тестирование

- Юнит-тесты логики колоды (shuffle/draw/empty/reshuffle) на Vitest.
- Ручная проверка в двух вкладках (хост + участник).

## Вне объёма (YAGNI)

Аккаунты, чат, таймеры, голосование «выполнено/нет», история сессий.

## Зависимости

Текст карточек от пользователя. До получения — seed-заглушка.
